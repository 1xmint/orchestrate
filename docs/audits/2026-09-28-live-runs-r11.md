# Live runs — round 11, three scenarios against `0d72567` (2026-09-29)

Round 10 (`03049ee`) could not exercise the review hold, the commit-claim
block, the cap comparison or the plugin-written checkpoint. Wave 12 landed
ten merges after it (`3aa9749` .. `0d72567`). Round 11 reads three recorded
runs to see what wave 12 changed for a person who cannot code: a delivery
with three helpers at the default cap (A), the same delivery at a patched
cap of four (B), and a twelve-meeting read that crosses two automatic
compactions (C).

## Method

- The plugin loads with `--plugin-dir` from pinned worktrees at `0d72567`
  (`<repo>/.claude/worktrees/live-r11`, `live-r11-cap4`, `live-r11c`); the
  installed copy is disabled with
  `--settings '{"enabledPlugins":{"orchestrate@orchestrate":false}}'`.
- `--model sonnet`, headless `-p`, `--output-format stream-json --verbose`,
  `--max-budget-usd 10`, `--debug-file` on. No permission flag; the streams'
  `init` reports auto mode.
- One fresh throwaway repo per run under `<tmp>`. Raw streams, debug logs and
  my helper scripts stay in `<scratch>/live12`; they hold machine paths and
  are not committed.
- **Staged change (B only).** The `live-r11-cap4` worktree has one edit,
  `maxConcurrent: 2` changed to `maxConcurrent: 4` at
  `skills/orchestrate/scripts/lib/policy.mjs:43` (the `live-r11` worktree
  still reads `2`). The real `<home>/.claude/orchestrate/profile.json` was
  never written.
- **Staged change (C only).** `CLAUDE_CODE_AUTO_COMPACT_WINDOW=100000` in the
  child's environment, to force compactions on a small task.
- **What the runs did not isolate.** They ran against the real `<home>`, so
  `<home>/.claude/orchestrate/profile.json` applied to all three. It contains
  `"policy": {"v":1,"workers":{"maxConcurrent":6}}`. That value is read after
  the code default and overrides both `2` and the patched `4` (see a).
- The stream records only `SessionStart` hooks. Advice from
  `PreToolUse`, `PostToolUse` and `PostCompact` exists only in the debug
  logs (`Hooks: Parsed initial response` lines); I read those.
  `Stop` and `SubagentStop` hooks that print nothing leave no debug line
  (see d, f, and Not verified).
- All three `.err` files are empty, and no debug line reports a hook
  finishing with a non-zero status.

Prompts, one line each:

- A and B, `prompt-helpers.md`: build a tool-library web app with a
  catalogue page, a borrow form and an admin page behind an
  environment-variable password; "do not write the three parts yourself:
  hand each one to a separate helper".
- C, `prompt-r8d.md`: read twelve evening minutes in `notes/`, write one line
  per evening (the decision, or "nothing decided") to `DECISIONS.md`, commit
  it, and say in plain words what was found; "Do not hand this to a helper".

## Per-run findings

### a. A and B — the cap-2 versus cap-4 pair

- The comparison the pair was built for did not happen. Both runs allowed
  all three helpers to run at once, with no refusal and no ask. At the
  default cap of 2 the third dispatch should have been refused with the
  guard's "N workers are already running (...), and the limit is M across
  Claude and Codex..." text (`lib/workers.mjs`, `concurrencyDecision`); it
  was not.
- **Cause.** `policy.workers.maxConcurrent` comes from the real
  `<home>/.claude/orchestrate/profile.json` (`6`) and wins over the code
  default `2` (`lib/policy.mjs:43`) and over the worktree's patched `4`. So
  the effective cap was 6 in both runs; the two runs are the same
  configuration run twice.
- What differs between them is noise, not the cap: A 436 s and $1.692; B
  540 s and $1.626 (B was 24% slower and 4% cheaper).
- Round 10's delivery run 0 cost $2.21 in 562 s and left 21 files staged and
  uncommitted; A and B both commit and both finish in under 10 minutes for
  about $1.6-$1.7.

### b. A and B — the price pair and the lead's cost sentence

- Lead sentence against the stream total (factor 1.5):
  - A: "about $1.67 of the $10 budget — most of it the three parallel builders
    (~$0.60–0.70 each), the rest my own merging and live-testing". Total

## Fixes these runs suggest, ranked

1. **Make the snapshot land at the boundary it names.** Write it from the
   `PostCompact` hook using what that hook is given, or on the first
   `PostToolUse` after a boundary, not only on the next compaction; write one
   for every compaction; raise the Goal cap or cut at a sentence end so the
   ask is never clipped; put the lead's real last message and a next action
   in it (c).
2. **Make the cards agree.** Do not append the pre-compaction reading to
   the `SessionStart:compact` card; use one capacity (180k or 200k); when the
   snapshot exists, stop asking for a checkpoint, or count the lead's own
   notes file; make the promised threshold match where compaction fires
   (~153k) (c).
3. **Let the review hold see a free-form dispatch.** Key the record to the
   helper (agent id or description) when there is no task id, so the hold can
   fire when a review-tagged helper returns (d).
4. **Fix the cost sentence at the source.** The list-price half of the tag
   is being read as what a helper costs; say "this run's total so far" or
   drop the list price after the first dispatch, so a lead cannot write
   "$1.50-$2 each" for a $1.63 run (b).
5. **Stop refusing a merged `git branch -d` and the worktree removals with
   it.** Either allow `branch -d` (git refuses unmerged branches itself) or
   split the chain; today the message tells a person who cannot code to edit
   `.orchestrator/allow-bash.json`. Add a clean-up step for
   `.claude/worktrees` (g).
6. **Make the live runs testable.** Run against an isolated home, or read the
   cap from the environment, so a cap test tests the cap (a).
7. **Keep the machinery out of the final message.** "harness", "worktree"
   and branch names reach the user in A and B (h).

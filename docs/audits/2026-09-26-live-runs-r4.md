# Live runs — round 4, a delivery big enough to need helpers (2026-09-26)

Rounds 1 and 3 (`2026-09-24-live-runs.md`, `2026-09-24-live-runs-r3.md`) ran
the three Part A scenarios; their delivery case was small enough that doing it
alone was the right call, so they never exercised the helper path. Round 4
runs one larger delivery against the audit branch at `6547c0f`, chosen so the
plugin's own rule ("do a step yourself when it fits in about eight tool calls;
hand over anything larger") should send work to helpers. The router split that
landed after `6547c0f` (`scripts/lib/brief.mjs`, `recover.mjs`,
`persist-words.mjs`) moves code between files and changes no behaviour, so this
evidence stands for the current head.

## Method

Same as round 3: the branch loaded with `--plugin-dir` from a detached worktree
pinned at `6547c0f` with both skill packages built, the installed copy disabled
for the child with `--settings '{"enabledPlugins":{"orchestrate@orchestrate":false}}'`,
`--model sonnet`, headless `-p`, `--output-format stream-json --verbose`,
`--max-budget-usd 5`, default permission mode (reported as `auto` in the init
event). The init event lists the plugin as `orchestrate@inline` version 0.16.1
with the eight agents and the one skill. One fresh throwaway repo under a short
temp path, with one empty commit; deleted after this write-up. The raw
stream-json transcript is kept in the session scratch folder `live5/` (not
committed: machine paths).

The prompt: a small Node web app for a neighbourhood tool library, no framework,
three parts that do not depend on each other (a catalogue page with a category
filter, a validated borrow-request form that refuses a tool already on loan, an
admin page behind a password from an environment variable), each with its own
tests on Node's built-in runner, a README, "I will not be able to answer
questions, so make sensible choices and tell me what you chose. Finish all
three parts."

Settings file: its modification time was read before and after the run and is
identical (12:25:42 local, both times). That time is from earlier the same day,
when the voicemode plugin's installer rewrote the file (it left a
`settings.json.bak-before-voicemode` at the same instant and added one disabled
`voicemode@voicemode` entry). Nothing on this branch touched it: the marker the
plugin checks was already `existing`, and the run left no write.

## What the hooks did

stream-json again reports no plugin hook responses (only the app's own
SessionStart events), as rounds 1 and 3 found; the full session transcript
under the app's projects folder shows them:

- The card was injected once on the first prompt, 1,613 characters, the text
  of `CARD` in `scripts/lib/card.mjs`.
- The brief line said no "What this is for" section was found and named the
  template. Wording flaw: when the folder searched is also the top folder it
  prints "between <path> and <path>", the same path twice.
- The context line fired twice, at ~43k and ~50k of ~200k, each ~110
  characters, from `context-check.mjs` (184 ms each).
- The plugin left its context record for the session under its state folder,
  with the lead's measured context (65,076 tokens from response usage) and
  the transcript offset. That is the proof the hooks ran end to end.
- No auto-compact tip, no changed-block, no recover notice: nothing to say,
  nothing said.

## The finding

The lead read the card and chose not to follow its helper rule. Its first
words: "I'll build this directly — it's a well-bounded, three-part app with no
ambiguity worth pausing on." It then made 23 tool calls itself, three times
the card's "about eight", and never opened the skill, a run ledger or a helper.

The outcome was still good for this user: finished in three minutes for $0.69,
every part tested, no questions. Three helpers through the coordinator would
have cost more in total (each re-reads its packet every step) and taken longer,
and in a headless run there is no later conversation for the lead's 65k of
context to crowd. So the rule was not wrong to break here, and the card is
guidance, not a gate.

What it means for the audit: the plugin has still not been seen dispatching a
helper in a live run on this machine. The delivery scores (finished, no
questions, plain final message) are earned; the coordination scores rest on the
unit tests of the guard and ledger, the field notes in the run's
`observations.md` (which do cover dispatches, from the lead's own session on
the installed copy), and reading, not on a transcript of this branch sending
work out. A live run that forces the helper path would need a task the lead
cannot finish alone within its context, which on a $5 cap and a single prompt
is hard to stage honestly; the audit should say the helper path is unmeasured
live rather than infer it.

Small fix worth making: the brief line's "between X and X" wording when the two
paths are the same.

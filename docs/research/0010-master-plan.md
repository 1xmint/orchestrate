Written 2026-10-02 against the work branch and the pilot's first result; it replaces revision 3 after five readers' findings. Every fact carries the file it was read from; what could not be checked says "unchecked".

"Your judgment": section 6 is the whole list of what is yours.

**Words used once and then assumed.** *Plain Claude* is Claude Code with no plugin and no command typed. A *hook* is a small script Claude Code runs at a fixed moment (a prompt typed, a tool about to run, Claude about to stop). *Keep-going* is the plugin's refusal to let Claude stop while the goal is open. A *helper* is a second Claude on a cheaper model given one bounded piece of work. The *bench* is seven small build tasks with hidden checks, five used now and two held back; an *arm* is one version run on all of them; a *run* is one attempt at one task. A *nudge* is a word you type to get work moving again. The *scorer* is the program that reads a run and says pass or fail. A *gate* is a check a change must pass before anything else counts: no more false "done" claims, and no safety stop removed (a safety stop is the hook that refuses a destructive or paid command, or the rule to ask first). *Headless* means run from a script with no screen. A *summary* is Claude Code squeezing a long conversation to make room; hook text does not survive it. The *work branch* is where changes sit before they ship. A *payload test* feeds a hook the exact message Claude Code would send and costs no usage. A *mod* is a newer kind of add-on that can draw on the screen (Claude Code 2.1.287 and up). *List price* is what a run would cost if paid per use; your subscription bills in usage windows, so list price is the stand-in we can measure. A *usage limit* is the five-hour or weekly cap on that subscription. The *record* is the three write-ups of your real sessions under docs/research/ (0007-findings-radar.md, 0007-findings-realorrug-a.md, 0007-findings-realorrug-b.md). The *per-run read* is the instruction text Claude reads because the plugin is installed: the skill body, the output style and the card.

## 2. What changes in this revision, and why

**A. Plain Claude is the yardstick, the loss is predicted before it is paid for, and the cut goes where the cost is.** You feel: no run bought to confirm what the record already says. 0.20.0 measured level with plain Claude at about 1.36x the cost and blamed the extra on Claude reading its own instructions (docs/research/0007-eval-release.md lines 101-109). The rule calls 1.15x a loss (bench/RULE.md line 15; evals/grade-kept.mjs line 304). Getting from 1.36x to under 1.15x means losing about a sixth of the whole cost, which is more than half of the extra. Hook notes cannot give that: every kind apart from the after-summary re-send adds about 1.5 KB per session in total (docs/research/0009-hook-bytes.md lines 10-27), and most fire only in long sessions. The per-run read is bigger and untouched: the skill body is 19,994 bytes, the output style 5,094, the card 2,196 of its 2,200 cap (counted on the work branch; the cap is in skills/orchestrate/scripts/lib/card.mjs). Stage 0 and Stage 2 add words, they do not remove them. So step 2e cuts the per-run read to a written byte target, step 5 writes the predicted cost ratio before any cap is written, and a predicted loss is not bought. Cost: none.

**B. The scorer and the counter are fixed before another run is paid for.** You feel: no more green runs that proved nothing, and no note cut on the word of a counter that could not see it. Cost: none.

**C. The restart problem is split by cause, provisionally.** You feel: "goes around in a loop all day" has three or four causes, and the biggest is already fixed. Two write-ups of the record cover the same days, so the three "Try again" presses appear in both (0007-findings-radar.md line 46; 0007-findings-realorrug-b.md line 27): the count is about sixteen restarts you typed by hand, not nineteen, and step 3 settles it with file and line. About ten were wording the plugin did not recognise ("continue", "resume", "whats left", "ok lets resume": realorrug-a lines 23-32; radar lines 45-50); Stage 0 matches them now. Two or three were waits that could never wake: about fourteen hours on a dead watcher, about four on a check that never reported back (realorrug-a lines 26-32; radar line 49). About four followed a usage limit (realorrug-a line 23; radar line 46; realorrug-b line 28), and one of those is also tied to a helper that ran out of turns and left a broken branch (realorrug-b lines 68-69). Plain Claude has the same limits; what it now also has is its own carry-on after one: automatic in a terminal, and on the Desktop app a tick "Auto-continue when limits reset" on the session-limit card, not the weekly one, which retries the interrupted turn (code.claude.com/docs/en/errors, fetched 2026-10-02; its default is not stated). So the plugin's job at a limit is to not get in the way: stay armed, write one honest pause record, let the host wake it. Cost: free work and payload tests.

**D. Interrupted work is proven hard enough that plain Claude can fail it, or nothing is claimed.** You feel: a release sentence you can trust. The scripted test cuts the first turn short and counts nudges after "continue" (bench/scenarios/resume.mjs lines 1-5, 163-165). If plain Claude also finishes with no nudge beyond the forced one, the test cannot tell the arms apart and the release says nothing about interrupted work. Cost: one plain run under its own cap (step 4).

**E. One place to look.** You feel: one line at the top that says "Working on: X", "Needs you: Y" or "Paused for the usage limit", in your words, so "is it stuck?" has an answer without typing. Plain Claude shows a spinner and a usage ring; it does not say what it waits for. Cost: free; judged by your next build (section 4).

**F. Faster means fewer refusals and round-trips, and they are counted.** You feel: a job that does not take three times as long because a helper was refused and re-sent. That is the record's biggest time cost: 562 seconds against 167 without the plugin, three of six helper sends refused (docs/audits/2026-09-28-live-runs-r10.md lines 94-105). Step 2a counts refusals and re-sends from your session records, so the trim covers what slows a session, not only what it prints. Cost: none.

# Release check: 0.19.0 against 0.18.0 (2026-10-01)

The release measurement for 0.19.0, required by AGENTS.md before a release.

Cost cap, set before any run: 25 dollars list price in all, counted against the
owner's Claude plan usage (`claude plugin eval` runs as the signed-in account; no
separate bill). Each command carries its own `--max-cost-usd` share.

Command, per case:

    claude plugin eval evals --case <name> --trust-plugin --no-publish \
      --allow-tools Write Edit --scaffold --keep-temp --max-cost-usd <share>

0.18.0 runs come from a detached checkout of main at 667a311 with this branch's
fixed graders and the new plan-request case copied in.

## The plan-request rules, corrected before the 0.19.0 runs

The first run of the new plan-request case, on 0.18.0, both arms, 3 runs each
($2.76), failed the same three rules in all six runs: plan-questions,
plan-steps-visible and plan-no-extra-scope. Both arms scored about 0.6, so the
case could not show any before-and-after difference. The judge (Haiku, the
default) keeps only its votes, not its reasons. So the six final plans were read
against each rule's FAIL clauses by hand. All six were sound plans:
- private notes stay on the laptop;
- the real files are named;
- a free shared-folder route is recommended and a website is warned off;
- two or three questions are asked.

What tripped the rules, and what changed (written before any 0.19.0 run, so the
rules were not fitted to the new build's output):

- **plan-questions** demanded a recommendation on every question. That includes
  questions only the owner can answer ("do you already share a OneDrive
  folder?"). It also wanted "who else could see" put as a question even when the
  plan says it plainly.
  - Now: a choice needs a recommendation, and a fact about the owner does not. The
    plan must say who else could see the notes and what it costs, not ask.
  - It still fails: a technical question, a choice with no recommendation, more
    than four questions, and a route that lets others in without saying so (the
    0.18.0 costly-fork wifi server).
- **plan-steps-visible** counted the owner's own commands (`add --shared`,
  `share 3`) and `notes.json` as programming terms. This owner types those
  commands.
  - Now: those count as plain, and a separate list of changed files is allowed.
  - It still fails: "add a shared field to the schema" as a step, and the words
    schema, field, endpoint, API, function, module.
- **plan-no-extra-scope** was failed by the small parts that make sharing work:
  unsharing, a mark in `list`, instructions. Asking whether the partner should
  edit was also counted as scope.
  - Now: those serve the request, and a question is not a step.
  - It still fails: partner editing, more people, a redesign, or moving all the
    notes, when any of these is a step.

All three rules now judge only the last message to the owner. 0.18.0 was rerun on
the corrected rules, so both versions face the same rules.

## The plan-request judge was shown the wrong thing (found after the 0.19.0 run)

The 0.19.0 run (plugin 0.583, without 0.667) failed plan-questions, plan-steps-visible and
plan-no-extra-scope in nearly every run on both sides, as 0.18.0 had. The report's "what the judge
was shown" starts at the session's setup message: each plan rule had `focus: trace`, so the judge
read the run's raw record as escaped JSON (the first and last 12 entries of a long one; see
https://code.claude.com/docs/en/plugin-evals#what-a-grader-can-look-at), not the plan. Three of the
rules say "judge only the assistant's last message to the owner".

- All five plan rules now use `focus: last_message`. plan-intent and plan-grounded judge the plan
  too, and on the record plan-grounded could credit a file Claude only opened.
- Rules that check that tests were run (three-session, misleading-bug, failed-check-report) keep
  `trace`; they need the record.
- Every plan-request score above is void as a measure. Both versions are rerun on the fixed rules.

## Results

Three runs per side, judge Haiku, `--allow-tools Write Edit` (no shell). Plan usage spent this
session on tests: $13.53 of the $25 cap ($2.76 and $2.81 on the void plan-request rules, $0.86 on
0.18.0 costly-fork, $5.56 on the four 0.19.0 cases, $1.54 on plan-request on both versions under the
fixed rules).

| Case | 0.19.0 with | 0.19.0 without | 0.18.0 with | 0.18.0 without |
|---|---|---|---|---|
| costly-fork | 1.00 | 0.56 | 1.00 | 1.00 |
| plan-request (fixed rules) | 0.92 | 0.88 | 0.92 | 0.88 |
| wrong-goal | 1.00 | 1.00 | not run | not run |
| three-session-continue | 0.83 | 0.83 | not run | not run |

What the numbers say, and what they do not:

- **costly-fork.** With the plugin, no run built anything before asking, in six runs across both
  versions. Without it, Claude built a wifi page in two of six. The 0.56 and 1.00 are the same plain
  Claude in two batches: three-run noise, not a change in 0.19.0. The release check's one bad
  plugin run (a wifi server with no password) did not recur, on either version, so this run cannot
  show that the 0.19.0 wording fixed it. It shows only that it did not break it.
- **plan-request.** Under the fixed rules every plan named real files, kept to the request and
  stated the goal. The rule that separates the sides is plan-questions (questions the owner can
  answer, a recommendation on each choice, who else could see the notes): with the plugin it passed
  2 of 3 on 0.19.0 and 1 of 3 on 0.18.0, without it 0 of 6. That is a plugin effect on the thing
  the owner asked for most, but three runs cannot separate the two versions. One 0.19.0 run also
  failed plan-steps-visible. No wording was added for it: the plugin already leads, and a change
  three runs cannot confirm is change for its own sake.
- **wrong-goal.** Both sides raised the conflict in every run. The plugin side was quicker (1 to 3
  turns against 5 to 6).
- **three-session-continue.** Both sides did the right step in every run and said honestly that
  nothing could be tested or saved (the run allows no shell). The rule failed, on both sides, when
  the final message did not name what comes next. One plugin run sent a helper to run the commands;
  it was blocked too and made that run cost $0.63 against about $0.17. That is waste the plugin
  caused.
- **Not measured:** misleading-bug and failed-check-report still cannot run on Windows.
- The judge's written reasons are shown only in the HTML report as the evidence it read, not as
  text; the JSON keeps votes.

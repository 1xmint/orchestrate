# Release check: 0.19.0 against 0.18.0 (2026-10-01)

The release measurement for 0.19.0, required by AGENTS.md before a release.

Cost cap, set before any run: 25 dollars list price in all, counted against the
owner's Claude plan usage (`claude plugin eval` runs as the signed-in account; no
separate bill). Each command carries its own `--max-cost-usd` share.

Command, per case:

    claude plugin eval evals --case <name> --trust-plugin --no-publish \
      --allow-tools Write Edit --scaffold --keep-temp --max-cost-usd <share>

0.18.0 runs come from a detached checkout of main at 667a311 with this branch's
fixed graders and the new plan-request case copied in.

## The plan-request rules, corrected before the 0.19.0 runs

The first run of the new plan-request case, on 0.18.0, both arms, 3 runs each
($2.76), failed the same three rules in all six runs: plan-questions,
plan-steps-visible and plan-no-extra-scope. Both arms scored about 0.6, so the
case could not show any before-and-after difference. The judge (Haiku, the
default) keeps only its votes, not its reasons. So the six final plans were read
against each rule's FAIL clauses by hand. All six were sound plans:
- private notes stay on the laptop;
- the real files are named;
- a free shared-folder route is recommended and a website is warned off;
- two or three questions are asked.

What tripped the rules, and what changed (written before any 0.19.0 run, so the
rules were not fitted to the new build's output):

- **plan-questions** demanded a recommendation on every question. That includes
  questions only the owner can answer ("do you already share a OneDrive
  folder?"). It also wanted "who else could see" put as a question even when the
  plan says it plainly.
  - Now: a choice needs a recommendation, and a fact about the owner does not. The
    plan must say who else could see the notes and what it costs, not ask.
  - It still fails: a technical question, a choice with no recommendation, more
    than four questions, and a route that lets others in without saying so (the
    0.18.0 costly-fork wifi server).
- **plan-steps-visible** counted the owner's own commands (`add --shared`,
  `share 3`) and `notes.json` as programming terms. This owner types those
  commands.
  - Now: those count as plain, and a separate list of changed files is allowed.
  - It still fails: "add a shared field to the schema" as a step, and the words
    schema, field, endpoint, API, function, module.
- **plan-no-extra-scope** was failed by the small parts that make sharing work:
  unsharing, a mark in `list`, instructions. Asking whether the partner should
  edit was also counted as scope.
  - Now: those serve the request, and a question is not a step.
  - It still fails: partner editing, more people, a redesign, or moving all the
    notes, when any of these is a step.

All three rules now judge only the last message to the owner. 0.18.0 was rerun on
the corrected rules, so both versions face the same rules.
